# 프론트엔드 통합 설계

작성일: 2026-11-18
작업 브랜치: feature/mix_all
상태: 사용자 승인 완료 (2026-11-18)

## 목표와 확정 범위

네 브랜치의 화면을 frontend 디렉터리의 단일 React+Vite 애플리케이션으로 통합한다. 기존 화면의 색상, 배치, 콘텐츠, 상호작용을 최대한 보존하고 공통 메뉴로 이동하게 한다. 신호 진단 전용 API는 백엔드에 합치지 않는다.

| 화면 | 소스 브랜치 | 경로 |
| --- | --- | --- |
| 소개·홈 | itro-page.sihyung | / |
| 신호 진단: 신호 현황·상세·교통량 분석 | 신호-진단 | /signals |
| 상권 분석 | anseong-sangkwon-(1234-홍기성) | /commercial |
| 교통 대시보드 | 정현수 | /traffic |

intro-page 및 revert 브랜치는 제외한다. 교통 대시보드는 정현수 브랜치 버전을 기준으로 하며 main에 추가된 지도 개선을 자동으로 섞지 않는다. 현재 main의 기존 구현은 보존한다.

## 앱 구조와 이동

frontend에 package.json, 잠금 파일, Vite 설정, index.html, src를 둔다. 기존 TSX 컴포넌트를 활용할 수 있도록 TypeScript를 기본으로 사용하고 JSX는 단계적으로 수용한다. React Router로 위 네 경로를 연결하고 화면을 지연 로딩한다.

src/app에는 라우터와 공통 메뉴, src/pages 아래에는 home, signals, commercial, traffic을 둔다. 각 페이지의 컴포넌트, 데이터, 스타일은 해당 디렉터리에 모은다. 소개 페이지의 포함 이미지들은 frontend의 자산으로 옮긴다.

공통 메뉴는 소개·신호 진단·상권 분석·교통 대시보드 네 링크와 현재 위치 표시를 제공한다. 좁은 화면에서도 메뉴를 사용할 수 있게 하며 각 페이지의 기존 헤더와 내부 탭은 유지한다. 홈의 관련 기능 링크도 실제 페이지로 연결한다. 존재하지 않는 경로에는 홈으로 돌아가는 안내를 제공한다.

## 기존 디자인과 동작 보존

HTML 소개·상권 페이지를 실제 React 컴포넌트로 전환한다. iframe이나 전체 HTML 삽입으로 감싸는 방식은 사용하지 않는다. 기존 DOM 조작은 React 상태, ref, effect로 옮기며 페이지를 떠날 때 지도·타이머·이벤트를 정리한다.

페이지별 최상위 클래스 또는 CSS Modules로 스타일 범위를 제한한다. body, :root, 공통 클래스 및 CSS 변수의 충돌을 막아 페이지 이동 순서에 따라 디자인이 달라지지 않게 한다. 소개의 스크롤 효과와 이미지, 상권 지도·반경·업종·공실 상호작용, 신호 현황·검색·상세·교통량 분석, 교통 대시보드의 차트와 선택 동작을 보존한다.

신호 진단 브랜치에는 참조만 있고 실제 파일이 없는 폰트가 있다. 누락된 파일을 임의로 만들어 넣지 않고 기존 대체 글꼴을 사용하며 한계를 문서화한다.

## API와 데이터

현재 backend 코드는 변경하지 않는다. 신호 진단 전용 API도 가져오거나 합치지 않는다. 통합 프론트엔드의 신호 진단 요청만 Vite 프록시를 통해 별도 API로 보낸다. 로컬 기본 연결 대상은 현재 실행 중인 127.0.0.1:8001이며 서버 환경변수 SIGNAL_API_TARGET으로 바꿀 수 있게 한다. 기존 백엔드 연결과 충돌하지 않도록 /api/signals-service 등의 전용 프록시 접두사를 사용한다.

신호 진단의 기존 외부 데이터 프록시 주소는 별도 설정으로 분리한다. 해당 프록시가 설정되지 않았으면 자동 호출하지 않고 전용 API의 저장된 정보를 조회한다. API가 꺼져 있거나 요청이 실패하면 실패 상태와 재시도 기능을 표시한다. 가상 데이터를 실시간 데이터처럼 표시하지 않는다. 검색·상세·조회 동작은 유지하고 새 API는 구현하지 않는다.

상권의 데모 모드와 기존 직접 API 호출 기능을 보존한다. 실데이터 사용에는 사용자 서비스키와 외부 API의 CORS 허용이 필요하다. 기존 상권 프록시 모드는 연결 설정이 있을 때만 사용할 수 있게 하며 프록시 서버 자체는 구현하지 않는다. 키는 저장소·예제 환경설정·로그에 기록하지 않는다.

교통 대시보드는 기존 시뮬레이션 데이터를 유지한다. 실데이터 연동이나 분석 로직의 신규 개발은 이번 범위에서 제외한다.

## 기존 파일과 실행

기존 frontend/asdf.html 및 ansung-traffic-ai 디렉터리는 삭제하지 않는다. 통합 앱의 실행 진입점은 frontend로 바꾸고 README에 설치·실행·API 선택 설정과 데이터 한계를 안내한다. 네 비교용 워크트리도 유지한다.

통합 완료 후 기존 5173 프론트엔드 프로세스를 종료하고 frontend의 Vite 서버를 같은 포트로 실행한다. 메인 백엔드와 별도 신호 API는 각자의 서버로 유지한다. 중복 서버는 만들지 않는다.

## 검증과 완료 기준

- frontend에서 의존성 설치, 타입 검사, 프로덕션 빌드가 성공한다.
- 네 화면의 경로와 소스 모듈이 정상 응답하고 API 프록시가 별도 신호 API에 연결된다.
- API 오류·데이터 변환처럼 통합 중 변경한 중요 로직은 필요한 범위에서 자동 검증한다.
- 원본 백엔드와 비교용 워크트리는 수정하지 않는다.
- 브라우저 검증은 사용자가 명시적으로 요청한 경우에만 수행한다. 빌드·CLI 검증만으로 시각적 동일성을 확인했다고 주장하지 않는다.
