# 프론트엔드 통합 구현 계획

작성일: 2026-11-18
브랜치: feature/mix_all
상태: 사용자 승인 완료 · 구현 진행 중
기준 설계: docs/design/frontend-integration.md (승인 완료)

## 실행 원칙

- frontend 안에서만 앱 통합을 진행한다. 백엔드 코드는 수정하거나 복사하지 않는다.
- 네 원격 브랜치의 확인된 커밋을 사용한다: 소개 769e33c, 신호 진단 d54dce5, 상권 e2fc4ac, 교통 대시보드 4338771. 워크트리가 사라져도 해당 Git 커밋에서 소스를 읽을 수 있다.
- 원본 frontend/asdf.html, ansung-traffic-ai, 비교용 워크트리를 보존한다. 파일 삭제는 수행하지 않는다.
- 각 작업 전에 파일을 다시 읽고 작업 후 변경을 확인한다. Git 전체 상태를 확인하되 모든 diff와 커밋은 해당 작업 경로로 제한한다.
- 각 작업은 구현·검증·검토가 끝나면 한국어 메시지로 개별 커밋한다. 실패한 검증이나 다른 세션과 겹친 수정이 있으면 해결하기 전 커밋하지 않는다.
- 설계·계획 문서는 구현 승인 후 별도 문서 커밋으로 기록한다. 아래 작업 체크박스와 커밋 결과는 마지막 문서 작업에서 갱신한다.
- 브라우저·Playwright 검증은 별도 요청 전까지 하지 않는다.

## 작업 1 — 단일 앱과 공통 메뉴 구성

대상: frontend/package.json, package-lock.json, index.html, vite.config.ts, tsconfig*.json, src/main.tsx, src/vite-env.d.ts, src/app/*, src/pages/*의 초기 진입점, .gitignore.

1. React 18 기반 Vite 앱에 TypeScript, React Router, 기존 화면에 필요한 Leaflet·Recharts·아이콘 의존성을 설정한다. 기존 프로젝트의 호환 가능한 버전을 우선하며 무관한 패키지 업그레이드는 피한다.
2. dev, build, typecheck 스크립트를 제공하고 JSX와 TSX의 단계적 공존을 설정한다. 신규 TS 코드의 엄격한 검사를 유지한다.
3. /, /signals, /commercial, /traffic 라우트와 공통 메뉴, 지연 로딩, 로딩·잘못된 경로 안내를 만든다. 페이지 진입점은 이후 각 작업에서 실제 화면으로 채운다.
4. 전역 스타일을 최소화하고 페이지별 최상위 클래스를 마련한다. 공통 메뉴는 좁은 화면에서 가로 스크롤 등으로 접근 가능하게 한다.
5. frontend의 node_modules와 dist가 Git에 추가되지 않도록 ignore 범위를 보완한다.

검증: npm ci, npm run typecheck, npm run build. 라우트 정의와 메뉴의 목적지 일치 여부를 검토한다.
커밋 주제: 프론트엔드 통합 앱과 공통 내비게이션 구성

## 작업 2 — 소개 HTML을 홈 화면으로 전환

대상: frontend/src/pages/home/*, frontend/src/assets/home/*.

1. 소개 원본 HTML의 문구·섹션·이미지·반응형 스타일을 React JSX/TSX와 페이지 전용 CSS로 옮긴다.
2. 포함된 이미지 데이터를 파일로 추출하고 이미지 형식·개수·참조 경로를 확인한다.
3. 스크롤에 따른 배경 전환 등 기존 동작을 effect/ref로 옮긴다. 이벤트·애니메이션을 unmount 시 정리한다.
4. 기존 화면 안의 기능 이동 링크를 통합 라우트에 연결한다. 구현 범위에 없는 기능을 새로 만들지는 않는다.
5. body/:root와 고정 배경 등의 스타일이 다른 페이지나 공통 메뉴에 영향을 주지 않게 제한한다.

검증: 타입 검사·빌드, 원본과 섹션/주요 문구/이미지 참조 대조, 효과의 등록·해제 검토.
커밋 주제: 소개 페이지를 React 홈 화면으로 통합

## 작업 3 — 신호 진단 화면과 별도 API 연결

대상: frontend/src/pages/signals/*, frontend/vite.config.ts, frontend/src/vite-env.d.ts, frontend/.env.example, 필요 시 frontend/tests/signals-*.

1. App, SignalList, DetailView, TrafficOptimizer, signal-utils를 페이지 구조로 이식한다. 신호 현황·검색·필터·상세·분석 탭을 유지한다.
2. 기존 스타일·변수·리셋을 신호 페이지로 한정한다. 존재하지 않는 폰트 파일 요청은 제거하고 기존 대체 글꼴을 사용한다. 원본 폰트 라이선스가 필요한 자산은 함께 보존한다.
3. /api/signals-service 접두사를 별도 API의 /api로 프록시한다. 서버 설정 SIGNAL_API_TARGET은 기본 http://127.0.0.1:8001을 사용한다.
4. 외부 동기화 주소는 VITE_SIGNAL_DATA_PROXY_URL 설정으로 분리한다. 미설정이면 외부 동기화를 생략하고 기존 저장 데이터 조회를 수행한다.
5. 응답 실패·API 연결 실패·빈 목록을 구별하고 재시도를 제공한다. 외부 동기화 미설정 상태에서 LIVE/실시간으로 오인할 표시를 조정한다.
6. 검색 변경으로 주기적 동기화가 불필요하게 반복되지 않게 effect 의존성을 검토한다. 페이지 이동·빠른 검색 시 오래된 응답이 최신 상태를 덮지 않도록 취소 또는 무효화한다.
7. 설정된 프록시 경로의 오류·JSON 응답 검증처럼 변경한 중요 로직에 좁은 범위의 자동 검증을 추가한다.

검증: 타입 검사·빌드, 관련 자동 검증, 실행 중인 별도 API에 대한 프록시 health/목록 응답. backend 경로에 변경이 없는지 확인한다.
커밋 주제: 신호 진단 화면과 독립 API 연결 통합

## 작업 4 — 상권 HTML을 React 화면으로 전환

대상: frontend/src/pages/commercial/*, 필요 시 frontend/tests/commercial-*, frontend/.env.example, frontend/vite.config.ts, frontend/src/vite-env.d.ts.

1. 원본 지도·설정 패널·요약·업종 분포·공실 후보 화면을 React 컴포넌트로 옮긴다.
2. 지도 중심·반경·데이터 모드·선택·공실 추가 상태를 React로 관리한다. Leaflet 지도와 레이어는 ref/effect로 연결하고 unmount 시 정리한다.
3. 기존 데모 데이터 생성·API 응답 변환·상권 분석 계산을 분리한다. 데모와 실제 데이터 표시를 명확히 유지한다.
4. 직접 API 호출의 서비스키 입력을 유지하되 영구 저장·로그 출력을 하지 않는다. 요청 취소와 오류·빈 결과 상태를 처리한다.
5. 선택적 COMMERCIAL_API_TARGET이 있을 때만 전용 Vite 프록시를 설정한다. 프록시 미설정 시 해당 모드를 비활성화하고 이유를 화면에 안내한다. 별도 서버는 구현하지 않는다.
6. 기존 계산 결과와 데이터 변환을 대표 입력·빈 값·잘못된 응답으로 자동 검증한다.

검증: 타입 검사·빌드·관련 자동 검증. 원본 기능 목록과 이식된 상호작용을 코드로 대조한다. 실제 서비스키가 없으면 실데이터 성공 여부는 미검증으로 기록한다.
커밋 주제: 상권 분석 페이지를 React로 통합

## 작업 5 — 교통 대시보드 이식

대상: frontend/src/pages/traffic/*.

1. 정현수 브랜치의 App, 지도/도식, 지표 카드, 진단 패널, 차트, 시뮬레이션 데이터와 서비스 함수를 가져온다.
2. 대시보드의 배치·색상·선택 동작·검색·새로고침을 유지한다. main의 별도 지도 개선은 섞지 않는다.
3. 페이지 전용 스타일로 격리하고 원본에서 실제로 지원하는 메뉴를 공통 라우트에 연결한다. 기존 미구현 기능을 작동하는 기능처럼 표시하지 않는다.
4. 조회·진단 effect의 정리와 시뮬레이션 안내를 유지한다.

검증: 타입 검사·빌드. 원본 데이터·지표 계산·선택 상태 흐름과 대조한다.
커밋 주제: 교통 대시보드를 통합 앱으로 이식

## 작업 6 — 통합 검증·실행 전환·문서화

대상: README.md, frontend/README.md, frontend/.env.example, docs/plans/frontend-integration.md, 필요 시 앞선 작업의 통합 결함 수정.

1. 설치·실행·타입 검사·빌드·자동 검증 명령, 네 라우트, 선택적 API 설정, 시뮬레이션 및 폰트 한계를 문서화한다.
2. Vite 프록시는 개발 서버 설정임을 명시하고 실제 배포에는 대응하는 리버스 프록시와 SPA fallback이 필요함을 안내한다.
3. 전체 타입 검사·빌드와 추가한 중요 로직 검증을 실행한다. 페이지별 CSS의 전역 누출, 해제되지 않은 이벤트·지도·타이머를 검토한다.
4. 현재 5173 포트의 PID와 실행 경로를 확인한 뒤 기존 메인 프론트엔드만 종료한다. frontend의 새 Vite 서버를 같은 포트로 실행한다. 메인 백엔드와 비교용 서버는 유지한다.
5. 네 경로와 진입 모듈, 신호 API 프록시의 HTTP 응답을 CLI로 확인한다. 빌드 성공만으로 화면의 시각적 동일성을 확인했다고 주장하지 않는다.
6. 검증용으로만 추가한 서버는 정확한 PID로 종료한다. 사용자용 통합 앱과 기존 요청한 비교 서버만 유지한다.
7. 작업별 커밋과 검증 결과, 남은 제한을 문서에 기록하고 경로별 diff로 변경 범위를 최종 확인한다.

검증: 전체 빌드·타입 검사·자동 검증 성공, 네 라우트 HTTP 성공, 신호 API 연결, backend 및 기존 보존 경로의 변경 없음, 의도한 포트 점유만 존재.
커밋 주제: 통합 프론트엔드 실행 안내와 검증 결과 정리
