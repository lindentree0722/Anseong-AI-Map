# 할 일

현재 구조는 React/Vite 단일 프런트엔드와 FastAPI 백엔드가 연결된 프로토타입이다. 아래 순서는 새 기능보다 실행 재현성과 데이터 신뢰도를 먼저 확보하는 기준이다.

## 1. 개발 환경과 검증 기준 고정

- [x] Python 3.15 설치 가능 여부를 확인한다. 2026-11-21 uv가 CPython 3.15.0b3(베타)를 설치했고 기존 잠금 파일로 동기화에 성공했다.
- [ ] 운영용 정식 Python 버전을 확정하고 필요하면 `backend/pyproject.toml`, `backend/.python-version`, `backend/uv.lock`, 실행 문서를 함께 맞춘다.
- [x] 가상환경이 없는 상태에서 `uv sync --project backend --locked`가 성공하는지 확인한다.
- [ ] 깨끗한 환경에서 `npm ci --prefix frontend`가 성공하는지 확인한다.
- [x] 백엔드 pytest를 실행한다. 2026-11-21 장소·교통 테스트 47개 통과, TestClient의 httpx 사용 중단 예정 경고 1건.
- [ ] 백엔드 pytest, 프런트 Node 테스트, 타입 검사, 프로덕션 빌드를 한 번에 확인하고 README의 과거 실행 결과를 현재 결과로 갱신한다.
- [ ] 네 경로(`/`, `/signals`, `/commercial`, `/traffic`)를 브라우저에서 확인하고 콘솔 오류와 모바일 레이아웃을 점검한다.

완료 조건: 새로 받은 저장소에서 문서의 명령만으로 설치·테스트·빌드·실행할 수 있다.

## 2. 배포 시 API 연결 방식 확정

- [ ] Vite 개발 프록시에만 의존하는 세 경로(`/api/traffic-overview`, `/api/signals-service`, `/api/commercial-service`)의 운영 배포 라우팅을 정한다.
- [ ] 신호 API(기본 8001)를 이 저장소의 배포 범위에 포함할지, 외부 서비스로 유지할지 결정하고 필수 환경변수를 문서화한다.
- [ ] API 실패 시 더미 데이터로 자동 전환되는 화면에서 더미 사용 여부가 항상 눈에 띄는지 확인한다.
- [ ] 상권 API 키는 저장·로그·커밋하지 않고 서버 프록시를 통해 전달하는 운영 구성을 우선한다.

완료 조건: 개발 서버 없이 빌드 산출물을 배포해도 각 API 경로가 동작하고, 실측·저장·더미 데이터가 화면에서 구분된다.

## 3. 백엔드 장소 API 최소 정비

- [x] `/places`의 입력·출력 모델을 정의해 임의 구조의 객체가 저장되지 않도록 검증한다. `name`과 `position: [위도, 경도]`를 사용하고 잘못된 일괄 요청은 전체 거부한다.
- [x] 프로토타입의 메모리 목록을 유지하고 재시작 시 사라진다는 사실을 `/docs` UI와 백엔드 README에 표시한다. 현재 장소 API를 사용하는 프런트 화면은 없다.
- [x] 조회·등록·전체 삭제의 정상 입력, 잘못된 입력, 테스트 간 목록 초기화를 pytest로 검증한다.
- [ ] 전체 삭제 API가 실제 사용자 데이터에 연결되기 전 인증 또는 관리자 경계를 설계한다.

완료 조건: API 계약이 명확하고 잘못된 입력을 거부하며, 데이터 소멸 조건이 사용자에게 드러난다.

## 4. 교통 실측 데이터의 유효 범위 확대

- [ ] 현재 단일 `ANSEONG_LINK_ID`와 수동 좌표만 받는 방식을 실제 분석 대상 링크 목록으로 확장할 요구사항을 정한다.
- [ ] 제공기관 응답의 속도 외에 교통량·집계 구간 등 신뢰할 수 있는 필드를 매핑하고 단위를 확인한다.
- [ ] 실측 응답에는 없는 혼잡도·대기시간·녹색 비율을 임의 생성하지 말고, 진단 가능한 지표와 `자료 부족` 상태를 구분한다.
- [ ] 제공기관 오류, 빈 결과, 시간대·좌표·행 수 검증을 유지하면서 실제 응답 샘플 기반 계약 테스트를 추가한다.

완료 조건: 화면의 진단 문구가 실제 수집 필드만 근거로 하며, 출처·관측시각·단위가 추적 가능하다.

## 5. 신호·상권 데이터 연동 완성

- [ ] 신호 상세 API의 기존 500 오류가 현재도 재현되는지 확인하고, 별도 API 저장소에서 원인 필드 매핑을 수정한다.
- [ ] 신호 데이터의 수집 주기, 최신성, 이력 보존 범위를 정하고 현재 신호처럼 오인되지 않게 표시한다.
- [ ] 상권 공공 API를 실제 서비스키로 한 번 검증하고 CORS, 페이지 제한, 빈 응답, 좌표계가 맞는지 확인한다.
- [ ] 더미 생성 결과와 실데이터 분석 결과를 동일한 형태로 유지하는 계약 테스트를 보강한다.

완료 조건: 두 화면 모두 실데이터 성공 경로와 실패 경로가 검증되고, 더미 데이터가 실데이터로 표시되지 않는다.

## 6. 저장소 정리

- [ ] 내용이 없는 추적 파일 `feat-sh`가 필요한지 확인한 뒤 불필요하면 삭제한다.
- [ ] `frontend/asdf.html`을 보존할 근거가 없다면 React 홈 화면과 중복되는 대형 인라인 자산을 제거하거나 보관 위치로 옮긴다.
- [ ] `backend/src/anseong_ai_map/__init__.py`의 콘솔 명령이 인사말만 출력한다. 실제 API 실행 명령으로 연결하거나 `[project.scripts]` 항목을 제거한다.
- [ ] 완료된 과거 계획 문서의 실행 중 PID·서버 상태 같은 시점성 기록은 현재 상태로 오해되지 않게 표시한다.

완료 조건: 모든 추적 파일에 현재 용도가 있고, README와 실행 명령이 실제 진입점을 가리킨다.

## 현재 상태 (2026-11-21, 백엔드 검증 반영)

- 이번 백엔드 작업은 `backend/main.py`, `backend/tests/test_places.py`, `backend/README.md`와 이 목록에 반영했다. 아직 커밋하지 않았다.
- 로컬 `py`는 Python 3.14.6을 가리키지만, 프로젝트 가상환경은 uv가 설치한 CPython 3.15.0b3를 사용한다. 기존 버전 설정과 잠금 파일은 유지했다.
- Node.js 26.13.1과 npm 12.2.2가 설치되어 있다. PowerShell의 `npm`은 실행 정책 때문에 막히지만 `npm.cmd`는 실행된다. `frontend/node_modules`는 없고 `backend/.venv`는 생성했다.
- 백엔드에는 교통 샘플·실측 파서 테스트가 있고, 프런트에는 API 폴백·상권 모델·신호 응답 테스트가 있다.
- 프런트는 네 화면이 React Router로 연결되어 있다.
- 교통 API는 기본 샘플 데이터와 선택적 경기도교통정보센터 단일 링크 조회를 지원한다.
- 장소 데이터는 전역 메모리에 저장되며 서버 재시작 시 사라진다.
- 신호와 상권은 설정된 외부 API가 없거나 실패하면 더미 데이터로 전환된다.
- 백엔드 의존성 설치와 테스트 47개 통과를 확인했다. 프런트 설치·테스트·빌드, 브라우저 점검, 실제 외부 데이터 연동은 이번 작업에서 검증하지 않았다.
