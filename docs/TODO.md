할 일
현재 구조는 React/Vite 단일 프런트엔드와 FastAPI 백엔드가 연결된 프로토타입이다. 아래 순서는 새 기능보다 실행 재현성과 데이터 신뢰도를 먼저 확보하는 기준이다.

[x] 가상환경이 없는 상태에서 uv sync --project backend --locked가 성공하는지 확인한다.
[ ] 깨끗한 환경에서 npm ci --prefix frontend가 성공하는지 확인한다.
[x] 백엔드 pytest를 실행한다. 2026-11-21 SQLite 전환 후 장소·교통 테스트 61개 통과, TestClient의 httpx 사용 중단 예정 경고 1건.

[ ] Vite 개발 프록시에만 의존하는 세 경로(/api/traffic-overview, /api/signals-service, /api/commercial-service)의 운영 배포 라우팅을 정한다.

3. 백엔드 장소 API 최소 정비
[x] /places의 입력·출력 모델을 정의해 임의 구조의 객체가 저장되지 않도록 검증한다. name과 position: [위도, 경도]를 사용하고 잘못된 일괄 요청은 전체 거부한다.
[x] 초기 프로토타입의 메모리 저장 제한을 문서화했다. 아래 SQLite 전환으로 영속 저장과 영구 삭제 동작에 맞게 갱신했다. 현재 장소 API를 사용하는 프런트 화면은 없다.
[x] 조회·등록·전체 삭제의 정상 입력, 잘못된 입력, 테스트 간 목록 초기화를 pytest로 검증한다.
[ ] 전체 삭제 API가 실제 사용자 데이터에 연결되기 전 인증 또는 관리자 경계를 설계한다.
완료 조건: API 계약이 명확하고 잘못된 입력을 거부하며, 데이터 소멸 조건이 사용자에게 드러난다.

SQLite로 장소 데이터 영속화
결정: Python 표준 라이브러리 sqlite3를 직접 사용한다. 기본 DB 파일은 backend/data/anseong-ai-map.db이며 /places만 전환한다. ORM이나 추가 의존성, 교통·신호·상권 이력 저장은 이번 범위에 포함하지 않는다.

[x] backend/database.py에 DB 경로와 초기화 코드를 추가한다. 실행 디렉터리와 무관하게 경로를 결정하고, 앱 시작 시 디렉터리와 테이블을 생성하되 기존 데이터를 유지한다. 테스트에서는 임시 DB 경로를 주입한다.
[x] places 테이블에 내부 정수 기본키 id, name, latitude, longitude를 정의하고 필수 값과 좌표 범위를 제약한다. 조회는 id 순으로 정렬하며 기존 중복 등록 허용 동작을 유지한다. 내부 ID는 API 응답에 추가하지 않는다.
[x] backend/main.py의 전역 목록을 DB 조회·등록·전체 삭제로 교체한다. 기존 Place 검증, position: [위도, 경도], 상태 코드, message 및 places 응답 구조와 빈 배열 동작을 유지한다.
[x] SQL 값은 매개변수로 전달하고 일괄 등록은 하나의 트랜잭션으로 처리한다. 실패 시 전체 롤백하며, 쓰기와 응답 목록 조회는 같은 트랜잭션에서 수행한다. 연결은 작업 단위로 열고 반드시 닫는다.
[x] 잠금 대기 시간을 5초로 제한하고 DB 잠금·쓰기 실패 시 503으로 응답한다. 초기화 실패는 시작 단계에서 드러내고, 오류 응답에 DB 경로나 SQL을 노출하지 않는다.
[x] backend/tests/test_places.py의 메모리 초기화 fixture를 테스트별 임시 DB와 앱 수명주기로 교체한다. 기존 입력·응답 테스트를 유지하고 재연결 후 보존, 삭제 후 재연결, 등록 순서·중복, 동시 등록, DB 쓰기·커밋·삭제 실패 시 롤백과 잠금 오류를 검증한다. 실제 개발 DB는 테스트에서 사용하지 않는다.
[x] .gitignore에 DB와 journal/WAL/SHM 파일을 제외한다. ANSEONG_DB_PATH로 동기화 폴더 밖의 로컬 경로를 지정할 수 있게 하고, README에 경로 설정과 서버 중지 후 백업·복원 절차를 기록한다.
[x] backend/README.md, /docs 설명과 이 문서의 현재 상태를 영속 저장 동작에 맞게 갱신한다. 기존 메모리 데이터의 전환 전 내보내기 절차와 공개 배포 전 쓰기·전체 삭제 권한 제한을 명시했다. 이번 검증은 임시 서버·DB만 사용했다.
[x] uv run --project backend python -B -m pytest backend/tests -q로 장소·교통 회귀 테스트 61개 통과를 확인했다. test_places_restart.py에서 임시 DB로 Uvicorn 프로세스를 세 번 시작해 재시작 후 등록·삭제 결과 보존까지 확인했다.
완료 조건: API 계약을 유지하면서 장소가 재시작 후에도 보존되고, 실패한 일괄 등록은 부분 저장되지 않으며, 테스트가 개발 DB를 변경하지 않는다.

현재 상태 (2026-11-25, 신호진단 지도 반영)
장소 API 검증 작업은 ea7ffd3에 커밋했다. 표준 sqlite3를 사용하는 장소 영속화 구현은 현재 작업 트리에 반영했다.
로컬 py는 Python 3.14.6을 가리키지만, 프로젝트 가상환경은 uv가 설치한 CPython 3.15.0b3를 사용한다. 기존 버전 설정과 잠금 파일은 유지했다.
Node.js 26.13.1과 npm 12.2.2가 설치되어 있다. PowerShell의 npm은 실행 정책 때문에 막히지만 npm.cmd는 실행된다. frontend/node_modules는 없고 backend/.venv는 생성했다.
백엔드에는 교통 샘플·실측 파서 테스트가 있고, 프런트에는 API 폴백·상권 모델·신호 응답 테스트가 있다.
프런트는 네 화면이 React Router로 연결되어 있다.
교통 API는 기본 샘플 데이터와 선택적 경기도교통정보센터 단일 링크 조회를 지원한다.
신호진단 지도는 시연용 도로 구간 선과 교차로 점을 표시한다. 구간별 속도와 선택 교차로의 대기시간·통행속도를 지도 위에서 확인할 수 있으며 실제 데이터의 도로 좌표와 대기 위치 매핑은 아직 미확보이다.
실제 연동에 필요한 교차로 목록, 방향별 교통량, 도로 구간 속도, 대기 정보, 신호 운영 정보와 출처·신선도 항목은 필요데이터.md에 정리했다.
장소 데이터는 SQLite 파일에 저장되어 재시작 후 유지된다. 기본 경로는 backend/data/anseong-ai-map.db이며 ANSEONG_DB_PATH로 변경할 수 있다.
신호와 상권은 설정된 외부 API가 없거나 실패하면 더미 데이터로 전환된다.
백엔드 의존성 설치는 앞선 작업에서 확인했고 SQLite 전환 후 테스트 61개가 통과했다. 임시 DB만 사용했으며 기본 개발 DB는 생성하지 않았다. 프런트 설치·테스트·빌드, 브라우저 점검, 실제 외부 데이터 연동은 이번 작업에서 검증하지 않았다.
