# 안성맞춤 AI 통합 프론트엔드

React 18 + Vite + React Router 기반의 단일 앱입니다. TypeScript를 기본으로 사용하고 기존 교통 대시보드 JSX를 함께 유지합니다.

## 실행과 검증

Node.js 22 이상을 권장합니다. 저장소 루트에서 실행합니다.

```sh
cd frontend
npm ci
npm run dev -- --port 5173 --strictPort
```

```sh
npm run typecheck
npm test
npm run build
```

타입 검사는 신규 TS/TSX를 대상으로 하며 기존 JS/JSX는 빌드와 핵심 로직 테스트로 검증합니다. `npm test`는 Node의 테스트 러너를 사용해 API 응답 검증, 상권 계산, 서비스키 인코딩과 오류 처리를 확인합니다.

## 선택적 API 설정

필요한 경우 `.env.example`을 참고해 `frontend/.env.local`을 작성하고 Vite를 재시작합니다. 비밀 값은 `VITE_` 변수에 넣지 마세요. `VITE_` 설정은 브라우저에 공개됩니다.

| 설정 | 기본값 | 용도 |
| --- | --- | --- |
| `VITE_SIGNAL_DATA_PROXY_URL` | 미설정 | 선택적인 외부 데이터 동기화 URL; 인증 비밀을 포함하지 않는 주소만 사용 |

## API 미구현·연결 실패 처리

백엔드 API가 아직 없거나 요청·응답 검증에 실패하면 화면은 같은 응답 구조의 더미 데이터를 사용합니다. 교통, 신호, 상권 화면은 더미 사용 여부를 사용자에게 표시합니다. 요청 취소는 폴백하지 않고 그대로 중단합니다.

새 백엔드 기능을 연결할 때는 `src/lib/api-fallback.mjs`의 `loadApiOrDummy`를 사용하고, API 응답과 동일한 필드의 더미 생성 함수를 함께 추가하세요. API 성공 응답이 있으면 해당 값을 우선하며, 더미 값에는 출처를 명시해야 합니다.

### 신호 진단

- 목록과 상세는 메인 FastAPI의 `/api/traffic-signals`에서 조회합니다. 교통량 직접 입력·CSV/JSON 분석 탭은 신호 API 없이 사용할 수 있습니다.
- 외부 동기화 URL이 미설정이면 해당 요청을 보내지 않습니다. 설정하면 약 60초 간격으로 데이터를 받아 메인 FastAPI의 `/api/traffic-signals/sync`에 저장합니다. 브라우저에서 접근 가능한 URL과 필요 시 CORS 설정이 필요합니다.
- 화면은 저장된 스냅샷을 보여줍니다. API에 초기 시뮬레이션 데이터가 있을 수 있어 실시간 신호로 표기하지 않으며, 저장 잔여시간을 현재 신호처럼 자동으로 감소시키지 않습니다.
- 방향별 상세·검색 요청은 페이지 이동 또는 대상 변경 시 취소합니다.
- ‘가상 대기시간’ 탭에서 교차로를 선택해 한국 표준시 기준 시간대별 평균과 집계 건수를 볼 수 있습니다.

### 상권 분석

- 기본 모드는 가상 데모입니다. 지도나 목록에서 서버 제공 공실을 선택하면 해당 위치의 점포, 업종 추천 근거, 주변 평균 신호 대기시간 및 개별 데이터 출처가 표시됩니다. 지도 중심 또는 직접 추가한 공실의 추천에서는 접근성 점수를 수동 입력할 수 있습니다.
- 직접 호출 모드에서는 사용자가 서비스키를 입력한 뒤 ‘이 위치 분석’을 누릅니다. 키는 컴포넌트 메모리에만 유지하고 저장소·브라우저 저장소·로그에 저장하지 않습니다. 원본의 내장 서비스키는 가져오지 않았습니다.
- 실데이터에는 공공데이터포털 이용 승인이 필요합니다. 브라우저 직접 호출은 원천 API의 CORS 허용도 필요합니다. 최대 5페이지(페이지당 1,000건)까지만 조회하고 한도에 도달하면 안내합니다.
- 서버 호출 모드는 메인 FastAPI의 `/api/commercial-service/storeListInRadius`를 사용합니다. 서비스키는 서버 환경변수 `COMMERCIAL_SERVICE_KEY`로 관리합니다.
- 지도 타일은 Esri/OpenStreetMap을 사용하므로 인터넷 연결이 필요합니다. 상권 데이터와 별도로 타일 요청이 실패할 수 있습니다.
- 직접 추가한 공실 후보는 현재 페이지에서만 유지됩니다. 서버 제공 공실과 처방의 출처는 영업점 조회 모드와 별도로 표시됩니다. 업종 추천은 규칙 기반 점수입니다.

## 디자인과 기존 파일

교통 대시보드는 Leaflet 지도에 API가 반환한 위치를 표시합니다. 지도 또는 목록에서 지점을 선택하면 해당 지점의 시연용 신호 진단 결과를 확인할 수 있습니다. 국도 상시교통량 차트는 이 교차로 시연 데이터와 별도입니다.

신호 진단 원본의 Pretendard/Geist 폰트 바이너리가 없어 시스템 대체 글꼴을 사용합니다. 소개·교통 화면의 Google Fonts와 지도 타일은 외부 연결에 의존합니다. 소개의 로그인은 미구현 상태로 표시합니다.

교통 대시보드는 `frontend/src/pages/traffic`에 통합했습니다. 로컬 백엔드를 8000번 포트에서 실행하면 `/traffic` 화면이 `/api/traffic/overview`를 통해 진단 결과를 읽습니다.

‘멈춤 없는 길 · 경로 비교’에서 가상 교차로 두 곳과 시간대를 골라 경로를 비교할 수 있습니다. 후보를 선택하면 지도에서 해당 경로가 강조되고 구간 통행시간, 가상 신호 대기시간, 추정 구간 수가 표시됩니다.

샘플 데이터와 진단 규칙은 `backend/data/traffic-sample.json`과 `backend/traffic.py`에서 관리합니다.

### 일반국도 시간별 상시교통량

- 제공된 엑셀 4개에서 2025년 9~12월 일별 기록 824건을 앱 데이터로 변환했습니다. 국도 17·38·45호선의 7개 관측지점에서 월과 지점을 선택할 수 있습니다.
- 시간대별 차트는 해당 월의 시간당 평균 교통량이며, 두 번째 차트는 일별 전일 합계입니다. 원자료의 단위는 대수입니다.
- 원자료에 안성 지점이나 좌표가 없습니다. 가평·용인·평택 지점을 인근 참고자료로 표시하며, 안성 교차로 지도·대기시간·속도·신호 진단은 시연 데이터로 분리해 안내합니다. 두 자료를 동일 지점으로 연결하지 않습니다.
- 정규화된 자료는 `src/pages/traffic/data/nationalHighwayTrafficData.mjs`에 포함되어 있으며, 집계 로직은 `src/pages/traffic/data/nationalHighwayTraffic.mjs`에 있습니다.

## 배포

`npm run build` 결과는 `frontend/dist`입니다. FastAPI가 `/`, `/signals`, `/commercial`, `/traffic`에서 이 빌드를 제공하고, 같은 주소의 `/api/*`에서 API 요청을 처리합니다. [단일 서버 실행 및 Render 배포](../backend/README.md#단일-서버-실행-및-render-배포)

## 검증 범위

가상 데이터 시연은 Node.js 22에서 의존성 설치, 타입 검사, 프로덕션 빌드를 확인했습니다. 390px 브라우저에서 네 화면의 가로 넘침 여부, 공실 지도 선택, 교차로별 대기시간, 후보 경로 전환, 조회 오류와 자료 부족 상태를 점검했습니다. 외부 지도 타일은 상권·교통 화면에서 별도로 실제 로딩을 확인했습니다. 서비스키를 사용하는 상권 실데이터와 외부 신호 동기화 검증은 남아 있습니다.

원본 계열 의존성을 유지했으며 설치 시 npm이 취약점 6건(높음 4, 보통 2)을 보고했습니다. 이번 변경에서 의존성의 주요 버전 교체는 수행하지 않았습니다.
