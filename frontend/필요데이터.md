# 신호진단 대시보드에 필요한 데이터

이 문서는 안성시 신호진단 대시보드를 실제 데이터로 전환할 때 필요한 항목을 정리합니다.
현재 지도와 진단 화면은 시연용 데이터로 동작하며, 실측 데이터가 없는 항목은 추정값이나 `0`으로 채우지 않습니다.

## 지금 가장 필요한 데이터

### 1. 교차로 기준 목록

다음 필드를 포함한 안성시 교차로 목록이 필요합니다.

| 항목 | 형식 | 예시 |
|---|---|---|
| 교차로 고유 ID | 문자열 | `ANS-001` |
| 교차로명 | 문자열 | `안성시청 사거리` |
| 행정동 | 문자열 | `봉산동` |
| 위도 | 숫자 | `37.0080982` |
| 경도 | 숫자 | `127.2797684` |
| 원천 교차로 또는 노드 ID | 문자열 | 기관의 교차로·노드 식별자 |

`position`은 반드시 `[위도, 경도]` 순서로 전달합니다.
공공 API가 좌표를 제공하지 않는 경우, 별도의 공식 교차로 좌표 매핑표가 필요합니다.

### 2. 방향별 교통량

신호 진단과 교차로 선택 화면에 아래 값을 실제로 제공해야 합니다.

- 관측 시각
- 교차로 ID
- 북·남·동·서 방향별 교통량
- 집계 구간
- 교통량 단위
- 수집 시각

권장 형식은 다음과 같습니다.

```json
{
  "id": "ANS-001",
  "sourceId": "원천교차로ID",
  "observedAt": "2026-11-25T16:00:00+09:00",
  "trafficVolume": 920,
  "trafficVolumeUnit": "vehicles/hour",
  "aggregationIntervalSeconds": 3600,
  "directions": {
    "north": 280,
    "south": 220,
    "east": 250,
    "west": 170
  }
}
```

대/시간과 대/5분은 집계 구간이 다르므로 혼합해서 계산하지 않습니다.

### 3. 구간 속도 또는 통행 속도

- 관측 시각
- 교차로 또는 도로 링크 ID
- 평균 속도(km/h)
- 방향 또는 진입 방향
- 원천 제공기관
- 데이터 수집 시각
- 실시간 또는 통계 구분

현재 백엔드는 경기도교통정보센터의 도로 링크 속도를 한 링크 단위로 조회할 수 있습니다.
안성시 내 여러 교차로를 실제 지도에 표시하려면 링크 ID별 좌표와 교차로 매핑이 필요합니다.

### 4. 교차로 대기 정보

실제 신호 진단을 위해 아래 항목이 필요합니다.

- 평균 대기시간(초)
- 방향별 대기시간(초)
- 대기행렬 길이(m)
- 관측 시각
- 관측 교차로 ID
- 데이터 수집 주기
- 신호 체계 또는 운영 기관

교통량이나 속도만으로는 대기시간과 혼잡도를 정확히 계산할 수 없습니다.

### 5. 신호 운영 정보

- 신호등 위치
- 신호주기 또는 현시 주기(초)
- 방향별 녹색시간(초)
- 보행자 녹색시간(초)
- 전구·현시 변경 이력
- 신호 연동 여부
- 관측 시각과 적용 시작 시각

녹색 신호 비율은 다음과 같이 방향별 실제 녹색시간이 확보된 경우에만 계산합니다.

```text
방향별 녹색시간 / 해당 방향의 신호주기
```

### 6. 시간대별 집계 데이터

차트에는 아래 형식의 실제 집계값이 필요합니다.

```json
[
  {
    "time": "18시",
    "volume": 1120,
    "wait": 94
  }
]
```

- 데이터가 없는 시간대는 `0`이 아니라 `null`로 전달합니다.
- 교통량과 대기시간은 같은 집계 기준 시각을 사용합니다.
- 과거 통계와 실시간 관측값을 같은 차트에 혼합하지 않습니다.

### 7. 데이터 출처와 신선도

모든 응답에는 다음 정보를 포함해야 합니다.

- 제공기관
- 원천 데이터 ID
- 관측 시각
- 수집 시각
- 데이터 기준일
- 실시간 또는 통계 구분
- 수집 실패 및 누락 여부

## 백엔드 정규화 응답

프런트엔드에 넘길 최상위 응답 형식은 다음과 같습니다.

```json
{
  "source": "제공기관명",
  "dataStatus": "observed",
  "generatedAt": "2026-11-25T16:10:00+09:00",
  "intersections": [],
  "hourlyTraffic": [],
  "roadSegments": [],
  "summary": {}
}
```

교차로 항목의 권장 필드입니다.

- `id`
- `sourceId`
- `name`
- `area`
- `position`
- `observedAt`
- `trafficVolume`
- `trafficVolumeUnit`
- `aggregationIntervalSeconds`
- `averageSpeed`
- `averageWait`
- `congestion`
- `status`
- `greenRatio`
- `directions`

측정하지 않은 값은 `null`로 유지합니다.
시연용 화면에서 임의로 만든 값은 실측 데이터처럼 표시하지 않습니다.

## 안성시 실측 연동에 우선 필요한 외부 확인

안성시 또는 경기도에 다음 범위를 문의하거나 활용 신청해야 합니다.

1. 안성시 교차로 위치와 공식 교차로 ID 제공 여부
2. 교차로별 방향 교통량 제공 주기
3. 교차로별 평균 대기시간 제공 여부
4. 신호주기와 방향별 녹색시간 제공 여부
5. 도로 링크 ID를 교차로와 연결할 수 있는 공식 매핑 제공 여부
6. API 호출 제한, 인증 방식, 갱신 주기와 이용 허가
7. 과거 통계와 실시간 관측값 중 어떤 데이터가 제공되는지

## 현재 연동 가능한 데이터

현재 백엔드 설정으로는 아래 실측 연동이 가능합니다.

- 경기도교통정보센터 도로 링크별 속도
- 도로 링크 원천 ID
- 링크 관측 시각
- 링크 대표 위도·경도

이 연동에는 다음 환경 변수가 필요합니다.

```powershell
$env:GITS_SERVICE_KEY = "경기도교통정보센터 발급 키"
$env:ANSEONG_LINK_ID = "확인된 안성시 링크 ID"
$env:ANSEONG_LINK_POSITION = "37.0080982,127.2797684"
$env:TRAFFIC_DATA_SOURCE = "observed"
```

API 키는 브라우저나 프런트엔드 환경변수에 넣지 말고 백엔드 서버 환경변수로만 관리합니다.

## 연동 전 협의 항목

- 실측 데이터 제공 범위와 갱신 주기
- 데이터 보관 기간
- 교차로별 좌표 및 공식 매핑
- 교통량 집계 기준
- 대기시간의 측정 방법
- 혼잡도 산식 및 기준값
- 신호주기와 녹색시간 제공 시점
- 서비스 중단·오류 시 사용자 안내 방식

## 연동 순서

1. 데이터 제공기관 또는 담당 부서에 위 항목을 문의합니다.
2. 교차로 ID와 원천 링크 또는 노드 ID 매핑표를 작성합니다.
3. API 키와 좌표 설정을 백엔드 환경변수에 등록합니다.
4. 원천 응답을 정규화해서 위 응답 형식으로 변환합니다.
5. 실측값을 화면에 표시하기 전에 결측값과 관측 시각을 검증합니다.
6. 실측 오류가 발생하면 시뮬레이션 자동 전환 대신 오류 또는 자료 부족 상태를 표시합니다.

> 데이터 출처와 제공 범위는 연동 전에 다시 확인해야 합니다.
